캡처 한 장에 앱 세 개.
그 흐름을 한 화면으로 줄였습니다.

EdgeShot은 기획, UI 디자인, 개발, 스토어 출시까지 혼자 진행한 Windows 캡처 도구입니다. 이 페이지는 무엇을 문제로 봤는지, 어떤 결정을 내렸는지, 그리고 그 결정을 어떻게 검증했는지를 개발자 관점에서 정리합니다.

배포

01

문제 정의

“캡처는 빠른데, 보내기까지가 느리다.”

캡처 도구로 찍기→그림판에서 화살표→다른 앱으로 개인정보 가리기→저장 경로·이름 정하기→메신저에 끌어 넣기
Alt + Shift + S→영역 선택 → 그 자리에서 표시·모자이크→Ctrl + C

누구를 위한 도구인가

업무 중 화면을 자주 캡처해 설명을 덧붙여 보내는 Windows 사용자. 출발점은 제가 직접 겪던 불편이고, 직접 쓰려고 만든 도구입니다.

목표

  • 캡처 → 표시 → 가리기 → 공유를 한 화면에서
  • 단축키 중심, 마우스 이동 최소화
  • 이미지가 내 PC 밖으로 나가지 않을 것

하지 않기로 한 것

  • 클라우드 업로드·공유 링크
  • 계정·로그인
  • 별도 편집기 창
02

제품 개발 과정

작게 만들어 내놓고, 쓰면서 고쳤습니다

  1. 1

    기획

    문제를 한 문장으로 정의하고, 개발 전에 프라이버시 기준 6가지부터 정했습니다.

  2. 2

    설계

    편집기 창 없는 오버레이 편집, 로컬 처리, 단축키 중심 툴바. 세 가지 원칙으로 기능 범위를 정했습니다.

  3. 3

    MVP 구현

    Python + PySide6로 영역 캡처, 도형·화살표·펜·텍스트·모자이크, 복사·저장을 구현했습니다.

  4. 4

    검증

    MVP 체크리스트 55개를 모두 통과시키고 자동 테스트로 회귀를 막았습니다.

  5. 5

    v0.1.0 출시

    PyInstaller로 빌드하고 MSIX로 패키징해 Microsoft Store에 무료로 출시했습니다.

  6. 6

    v0.1.1 개선

    그린 뒤에도 고칠 수 있도록 크기·끝점 조정을 넣고, 모자이크 강도와 설정 창을 더했습니다. 실기기 확인 뒤 스토어에 다시 제출했습니다.

03

쓰면서 찾은 불편

직접 쓰면서 걸린 점을 기록하고, 다음 버전의 범위로 삼았습니다

쓰면서 걸린 점v0.1.1에서 바꾼 것
그린 도형이나 모자이크 영역의 크기를 다시 바꿀 수 없음사각형·원·펜·모자이크 영역 크기 조절
화살표 방향을 고치려면 지우고 다시 그려야 함화살표 양 끝점을 끌어 조정
가리는 정도를 고를 수 없음모자이크 강도 6 / 10 / 16
전역 단축키가 고정되어 다른 앱과 겹칠 수 있음설정 창에서 단축키 변경
캡처할 때마다 색과 굵기를 다시 골라야 함마지막으로 쓴 스타일 기억
저장할 때마다 위치와 형식을 정해야 함기본 저장 폴더와 PNG / JPG 지정

가리기 방식도 쓰면서 바꿨습니다. 처음에는 블러(Blur)였지만 모자이크(pixelate)로 바꿨습니다.

04

프로덕트 디자인

앱의 경험과, 그 경험을 설명하는 랜딩의 역할을 함께 설계했습니다

앱 설계 결정 3가지

ADR-1

편집기 창 없이, 캡처 오버레이에서 바로 편집

결정
영역을 고른 그 화면 위에 툴바를 띄우고 사각형·원·화살표·펜·텍스트·모자이크를 그립니다. 그린 뒤에도 크기와 끝점을 다시 조정할 수 있습니다.
이유
창 전환이 생기는 순간 “앱 세 개” 문제로 돌아가기 때문입니다.
대가
오버레이 코드가 한 파일(overlay.py, 약 73KB)에 몰렸습니다. 동작 변경 없이 인라인 텍스트 편집기와 주석 핸들 모듈로 분리했습니다.
ADR-2

모든 처리는 내 PC 안에서

결정
네트워크 전송, 클라우드 업로드, 계정이 없습니다. 앱이 쓰는 파일은 사용자가 저장한 이미지와 설정 파일(%APPDATA%\EdgeShot\settings.json) 하나입니다.
이유
업무 화면에는 개인정보가 섞여 있기 마련이라, “가리기 전 원본”이 밖으로 나갈 경로 자체를 만들지 않았습니다.
대가
공유 링크 같은 편의 기능은 포기했습니다. 공유는 클립보드 복사(Ctrl + C)로 해결합니다.
ADR-3

단축키 중심 툴바

결정
도구마다 한 글자 단축키(V R O A P T B)와 Ctrl + Z / Y / C / S, Esc를 둡니다. 전역 단축키는 기본 Alt + Shift + S이고 v0.1.1부터 바꿀 수 있습니다.
이유
캡처 직후 손이 키보드에 있는 경우가 많아, 툴바를 찾으러 마우스를 옮기는 일을 줄이려 했습니다.
대가
전역 단축키는 다른 앱과 겹칠 수 있습니다. 새 키를 먼저 등록하고 성공했을 때만 이전 키를 해제하며, 등록에 실패하면 트레이 아이콘이 비활성 상태로 바뀌어 알려 줍니다.

프라이버시 기준 6가지

네트워크 전송, 외부 서비스, 데이터 수집, 클라우드 업로드, 임시 파일, 계정. 개발 단계에서 가장 먼저 고려한 기준입니다.

툴바와 프리셋

도구 순서 V R O A P T B, 선 굵기 1 / 2 / 4, 글자 크기 12 / 16 / 24, 모자이크 강도 6 / 10 / 16.

랜딩 기획: 랜딩이 하는 일

핵심

제품을 이해시켜 신뢰를 만들고, 다운로드로 연결합니다. 기능 이름보다 사용 장면을 먼저 보여 주고, 처리 방식(로컬 전용)을 구체적으로 설명합니다.

부가

개발 서사. 더 알고 싶은 사람을 위해 푸터에서 이 페이지로 연결합니다.

웹 디자인

랜딩 진행 순서

  1. ①디자인 시안과 콘텐츠 정비
  2. ②이미지 디테일과 툴바 디테일

기능 이름을 나열하기보다 실제로 쓰는 장면을 보여 주는 데 집중했습니다. 그래서 아이콘 카드를 짧은 동작 데모로 바꾸고, 모바일에서도 같은 흐름이 읽히도록 정리했습니다.

06

구현 메모

작지만 사용자 경험에 직접 닿는 부분들

값은 한 곳에서

선 굵기 1 / 2 / 4, 글자 크기 12 / 16 / 24처럼 프리셋 값을 하나의 기준(SSOT)으로 두고 문서의 옛 값은 기록으로만 남겼습니다. 버전 번호도 edgeshot/__init__.py 한 곳에서 읽어 빌드 정보에 넣습니다.

마지막 스타일 기억

v0.1.1에서 마지막으로 쓴 색과 굵기를 기억하고, 기본 저장 폴더와 PNG/JPG 형식을 고를 수 있게 했습니다. 모두 같은 설정 파일에 저장됩니다.

시작 프로그램은 기본 꺼짐

Windows 시작 시 실행은 MSIX StartupTask로 구현하고 기본값을 꺼 두었습니다. 사용자가 켜기 전에는 아무것도 자동 실행되지 않습니다.

빌드가 사용자 앱을 건드리지 않게

검증 스크립트가 이름이 EdgeShot으로 시작하는 프로세스를 모두 종료해, 스토어에서 설치한 앱까지 꺼질 수 있는 문제를 발견했습니다. 자기가 띄운 프로세스만 종료하도록 고치고, 빌드 결과물도 버전별 폴더로 나눠 이전 릴리스 기록이 지워지지 않게 했습니다.
